# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Git rules
- Never push (`git push` or anything else that updates a remote) unless the user explicitly asks for it in the current request.
- Never open, edit, comment on, merge or close pull requests (`gh pr ...` or the GitHub API), even if asked to push.

## Stack
- React 19 + TypeScript (`.ts`/`.tsx` only, no plain JS), bundled with Vite. npm is the package manager. Linting uses oxlint (`.oxlintrc.json`).
- Capacitor 8 wraps the Vite build (`dist/`) into the native Android project in `android/`. The app ID is `com.example.cantoninfo` (a placeholder), set in `capacitor.config.ts`.
- The only target is Android. There is no iOS platform and no web deployment.
- Web code lives in `src/` and starts at `src/main.tsx` → `src/App.tsx`. `android/` is generated by `cap add android`, but it is committed and may be edited by hand for native features.

## Target device: Tecmashin LED43, Android 11 (API 30)
- **Kiosk / display-only:** the screen shows information and has no touch, keyboard or remote input. Don't build interactive UI such as forms, buttons or hover states, and don't rely on user gestures. Anything that needs a user gesture in a WebView (audio autoplay, fullscreen requests) has to be handled on the native side or avoided.
- Kiosk behaviour is native code in `android/app/src/main/java/com/example/cantoninfo/`:
  - `MainActivity` keeps the screen on (`FLAG_KEEP_SCREEN_ON`) and hides the system bars in immersive mode. It re-hides them on resume and focus. `capacitor.config.ts` also sets `SystemBars.hidden`, and `index.html` uses `viewport-fit=cover`.
  - `BootReceiver` (registered in `AndroidManifest.xml`) launches `MainActivity` on `BOOT_COMPLETED`. Android 10+ blocks background activity starts, so on the device the app needs a one-time `adb shell appops set com.example.cantoninfo SYSTEM_ALERT_WINDOW allow`. The app must also be opened once after install, because Android doesn't send boot broadcasts to apps that have never run.
  - Landscape lock is not implemented.
  - `cap sync` does not overwrite these files. Only regenerating `android/` would.
- Design for a large landscape screen viewed from a distance. Size text with viewport units (`vw`/`vh`) as `src/index.css` does, and check the device's real resolution before hard-coding pixels.
- The device's Android System WebView may be old and may not update through Play. `vite.config.ts` sets `build.target`/`cssTarget` to `chrome83` (Android 11's launch WebView). Raise it once the real version is known (adb `dumpsys package com.google.android.webview`, or `chrome://inspect`). Syntax gets transpiled, but newer runtime APIs are not polyfilled.
- `vite.config.ts` uses `base: './'`. Keep asset URLs relative.
- `minSdkVersion` is 24 (in `android/variables.gradle`) and must stay ≤ 30. The app is sideloaded, so Play target-SDK rules don't apply.

## Commands
- `npm run dev`: Vite dev server for quick UI work in a desktop browser
- `npm run build`: type-check (`tsc -b`) and build into `dist/`
- `npm run lint`: oxlint
- `npm run android:sync`: build, then `cap sync android` to copy `dist/` and plugin changes into `android/`. **Run this after every web change** before building the APK.
- `npm run android:run`: build and deploy to a connected device (`adb devices` lists IDs; the LED43 can be reached with `adb connect <ip>:5555`)
- `npm run android:apk`: sync, then `./gradlew assembleDebug`. Output goes to `android/app/build/outputs/apk/debug/app-debug.apk`
- `adb install -r <apk>`: install or update on the device
- Debug the WebView from desktop Chrome at `chrome://inspect`. Debug builds allow this by default.

Android builds need JDK 21 (for Capacitor 8) and the Android SDK, found through `ANDROID_HOME` or `android/local.properties`.

No test framework is set up yet.
